# 0.3.0 release documentation audit

Audited on 2026-11-28 against main
[`f5d351c7c0ef4ec6ee3deb41ca78aa494fb1cbc0`](https://github.com/Limen-Neural/brainstem-daemon/commit/f5d351c7c0ef4ec6ee3deb41ca78aa494fb1cbc0).
This is the evidence for the implementation snapshot reviewed for
[LIM-1535 / #81](https://github.com/Limen-Neural/brainstem-daemon/issues/81).
The [parent release record, LIM-1447](https://linear.app/rpd-34/issue/LIM-1447),
owns qualification and the publication decision. This commit is the audit
baseline, not an assertion that a release SHA has been selected.

## Implemented and verified on the baseline

- [#72](https://github.com/Limen-Neural/brainstem-daemon/pull/72) and
  [#73](https://github.com/Limen-Neural/brainstem-daemon/pull/73) reject
  non-finite ingress. [#78](https://github.com/Limen-Neural/brainstem-daemon/pull/78)
  validates config/overflow before runtime startup.
  [#74](https://github.com/Limen-Neural/brainstem-daemon/pull/74) and
  [#77](https://github.com/Limen-Neural/brainstem-daemon/pull/77) bound PUB
  buffering and shutdown. PUB delivery remains best-effort.
- [#95](https://github.com/Limen-Neural/brainstem-daemon/pull/95),
  [#104](https://github.com/Limen-Neural/brainstem-daemon/pull/104), and
  [#109](https://github.com/Limen-Neural/brainstem-daemon/pull/109) establish
  locked `neuromod` 0.7.0, Rust 1.99.0 / repository-only package exclusions,
  and optional `corpus-ipc` 0.2.1. The default library constructors still
  select stub; the optional binary build wires ZeroMQ. The crates.io
  sparse index showed [neuromod](https://index.crates.io/ne/ur/neuromod)
  0.7.0 and [corpus-ipc](https://index.crates.io/co/rp/corpus-ipc) 0.2.1
  present and not yanked, and returned 404 for the
  [brainstem-daemon entry](https://index.crates.io/br/ai/brainstem-daemon).
  The index result does not verify publishing rights.
- [#79](https://github.com/Limen-Neural/brainstem-daemon/pull/79) qualifies
  the archive; [#105](https://github.com/Limen-Neural/brainstem-daemon/pull/105)
  adds the [bundled live fixture](../tests/fixtures/live/MANIFEST.md) and
  positive CLI live readiness. It is a synthetic, nonblank LIF checkpoint.
  Restore still rejects `output_weights` and unsupported checkpoint shapes.
  Reward-driven weight updates are disabled on restore; engine dynamics
  still run. No trained-model fidelity or general runtime usefulness is
  established by these checks.
- [CI run 46024881887](https://github.com/Limen-Neural/brainstem-daemon/actions/runs/46024881887)
  checked that exact baseline: rustfmt, Linux/macOS/Windows stub, Linux
  `corpus-ipc`, and packaged release passed. The run lists
  `package-qualification-f5d351c7c0ef4ec6ee3deb41ca78aa494fb1cbc0`;
  see [artifact contents and reproduction instructions](ci.md#cargo-archive-release-qualification).
  This is evidence from the baseline run, not evidence on the docs PR or a
  future release revision.

## Documentation changes and open gates

- [README](../README.md) now has checkout-based CLI and library examples,
  a self-contained live fixture, and the current feature/restore contract.
  [CHANGELOG](../CHANGELOG.md) rolls the verified implementation into
  pending 0.3.0, without calling repository history a registry release.
  [Crate rustdoc](../src/lib.rs) adds a runnable stub example and the
  current backend and checkpoint limits. [CI](ci.md) describes both live
  readiness and the remaining publication checks.
- The PR validation record should cover local documentation links, CLI
  configurations, library examples, strict rustdoc, and archive checks
  on the actual proposed commit. Rerun CI and retain the artifact for the
  final selected release SHA.
- DeepSource Rust is green on the audit baseline. The separate generic
  diagnostic-identity review on
  [PR #65](https://github.com/Limen-Neural/brainstem-daemon/pull/65#discussion_r4091682841)
  remains unresolved at the baseline and needs a verified fix or recorded
  maintainer disposition under
  [LIM-1449](https://linear.app/rpd-34/issue/LIM-1449).
- Registry owner/permission, maintainer authorization, publication,
  version-pinned registry install/consumer checks, docs.rs build, and
  release notes/tag are unverified.
- This audit qualifies the documented repository-local workflow. It does not
  establish compatibility with externally published trained sidecars,
  accelerator integration, or practical runtime usefulness.
